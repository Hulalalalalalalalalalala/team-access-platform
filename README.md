# sealmark

sealmark 提供命令行版本查询、本地文件的 SHA-256 内容摘要计算，以及把当前
文件与已保存的摘要直接核对的功能，用于检查文件内容是否发生变化。

## 构建

```sh
cmake -S . -B build
cmake --build build
```

依赖：C++20 编译器与 OpenSSL（libcrypto）。若 OpenSSL 不在系统默认路径，
可通过 `OPENSSL_ROOT_DIR` 或 `PKG_CONFIG_PATH` 提示其位置。

## 用法

```sh
sealmark --version                       # 打印版本号
sealmark digest <文件路径>                # 计算文件的 SHA-256 摘要
sealmark verify-digest <文件路径> <摘要>  # 核对文件内容是否与摘要一致
```

### 版本查询

```sh
./build/sealmark --version
```

输出：

```text
sealmark 0.1.0
```

### 文件摘要

```sh
./build/sealmark digest ./文档/report.pdf
```

- 输入对象限普通文件。摘要覆盖文件从开头到结尾的全部原始字节：文本与
  二进制文件按同一规则处理，不解码文本，不去掉换行、空白或字节顺序标记，
  也不把文件名、路径、大小或修改时间计入摘要。因此内容相同而名称或所在
  目录不同的文件会得到相同结果；空文件是有效输入。路径作为一个完整参数
  传入，含空格或中文的路径加引号即可。
- 成功时标准输出只写一行 `sha256:<摘要>`（摘要为 64 个小写十六进制字符，
  行末有换行），退出码为 0。例如：

  ```text
  sha256:d30520a932d453073ffd17a1d6ee000630fa6066e7d43ea5caa88d67eaf28237
  ```

- 失败时标准输出为空，标准错误给出说明原因的信息：
  - 路径不存在、指向目录或其他非普通文件、没有读取权限、读取或计算
    失败：退出码为 1，错误信息中包含传入的路径。
  - 缺少路径、空路径、多传参数或未知命令等用法错误：打印上述用法说明，
    退出码为 2。

### 核对文件摘要

先保存一份 `digest` 的输出作为记录，之后用一次操作确认文件内容是否仍与
记录一致。预期摘要直接使用 `digest` 命令输出的那一整行内容（`sha256:`
加 64 个小写十六进制字符；行末换行不属于参数，不要把换行带进参数）：

```sh
./build/sealmark verify-digest ./文档/report.pdf \
  sha256:d30520a932d453073ffd17a1d6ee000630fa6066e7d43ea5caa88d67eaf28237
```

- 核对对象与 `digest` 相同：文件从头到尾的全部原始字节，不做任何文本
  转换，换行、空白和二进制零字节都参与计算，文件名和其他文件属性不
  参与。文件移动或改名后，只要内容相同就会匹配；空文件也能核对。
  读取以固定大小的分块流式进行，内存占用不随文件大小增长，且核对过程
  只读文件、不改写文件。
- 当前文件摘要与预期一致时，标准输出只写一行 `match`，标准错误为空，
  退出码为 0：

  ```text
  match
  ```

- 文件读取和计算成功但摘要不同（内容已变化）时，标准输出只写一行
  `mismatch`，标准错误为空，退出码为 3：

  ```text
  mismatch
  ```

  两种结果都以换行结尾。
- 用法错误（缺少参数、多传参数、空路径，或预期摘要不符合
  `sha256:` 加 64 个小写十六进制字符的严格形式——不接受省略前缀、
  大写字符、其他算法名称、额外空白或尾随内容）：标准输出为空，标准
  错误打印包含 `verify-digest` 的用法说明，退出码为 2。参数和文件
  同时有问题时，优先按用法错误处理。
- 路径不存在、对象不是普通文件、无法读取或摘要计算失败：标准输出
  为空，标准错误说明原因并包含传入的路径，退出码为 1。

注意：这个功能只能核对文件内容与你**已有的摘要记录**是否一致。它不验证
摘要来自哪里，因此匹配结果不证明发布者身份，也不代表任何数字签名有效；
若需要确认发布者身份或签名，应使用带签名验证的机制。
