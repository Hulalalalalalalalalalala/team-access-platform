# sealmark

sealmark 提供命令行版本查询、本地文件的 SHA-256 内容摘要计算、按已保存的
摘要核对文件内容，以及公钥指纹查询，用于检查文件内容是否发生变化、核对来自
不同渠道的公钥文件是否代表同一把公钥。

## 构建

```sh
cmake -S . -B build
cmake --build build
```

默认构建只需要：

- 支持 C++20 的编译器（构建过程中不需要 C 编译器）；
- OpenSSL 开发文件（libcrypto 的头文件与库）。

若 OpenSSL 不在系统默认路径，可通过 `OPENSSL_ROOT_DIR` 或
`PKG_CONFIG_PATH` 提示其位置；缺少 OpenSSL 时配置会直接失败。默认构建
不会查找 Python，也不会构建任何测试辅助内容。

### 运行回归测试

回归测试默认关闭。需要时在配置阶段显式开启：

```sh
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build
```

开启测试需要额外准备：

- Python 3 解释器；如需指定解释器，可用 `-DPython3_EXECUTABLE=/路径/python3`，
  测试只会使用配置时选定的这个解释器；
- 该解释器环境中可导入的 Python [cryptography](https://pypi.org/project/cryptography/)
  包（`key-id` 测试用它独立生成和解析公钥）；
- 在 Linux 上还需要可用的 C 编译器，用于构建读取故障、读取中断与文件
  类型检查的测试辅助库；其他平台会按现有规则自动跳过这些辅助场景。

若缺少上述任何一项，配置阶段就会失败并说明缺的是什么；不想准备测试
环境时，不开启 `BUILD_TESTING`（或显式设为 `-DBUILD_TESTING=OFF`）即可
照常只构建 sealmark 程序本身。

## 用法

```sh
sealmark --version                  # 打印版本号
sealmark digest <文件路径>           # 计算文件的 SHA-256 摘要
sealmark verify-digest <文件路径> <预期摘要>
                                    # 用已保存的摘要核对文件内容
sealmark key-id <公钥文件路径>       # 查询公钥的稳定指纹
```

### 版本查询

```sh
./build/sealmark --version
```

输出：

```text
sealmark 0.1.0
```

### 文件摘要

```sh
./build/sealmark digest ./文档/report.pdf
```

- 输入对象限普通文件。摘要覆盖文件从开头到结尾的全部原始字节：文本与
  二进制文件按同一规则处理，不解码文本，不去掉换行、空白或字节顺序标记，
  也不把文件名、路径、大小或修改时间计入摘要。因此内容相同而名称或所在
  目录不同的文件会得到相同结果；空文件是有效输入。路径作为一个完整参数
  传入，含空格或中文的路径加引号即可。
- 成功时标准输出只写一行 `sha256:<摘要>`（摘要为 64 个小写十六进制字符，
  行末有换行），退出码为 0。例如：

  ```text
  sha256:d30520a932d453073ffd17a1d6ee000630fa6066e7d43ea5caa88d67eaf28237
  ```

- 失败时标准输出为空，标准错误给出说明原因的信息：
  - 路径不存在、指向目录或其他非普通文件、没有读取权限、读取或计算
    失败：退出码为 1，错误信息中包含传入的路径。
  - 缺少路径、空路径、多传参数或未知命令等用法错误：打印上述用法说明，
    退出码为 2。

### 核对摘要

先把此前某次 `digest` 输出的整行 `sha256:<摘要>` 保存下来，之后用一次操作
确认文件当前内容是否仍与记录一致：

```sh
./build/sealmark verify-digest ./文档/report.pdf \
  sha256:d30520a932d453073ffd17a1d6ee000630fa6066e7d43ea5caa88d67eaf28237
```

预期摘要直接使用 `digest` 命令输出的那一行内容（命令行参数本身不带行末换行，
用引号包裹即可）。文件只被读取，不会被改写。

- 匹配（文件当前摘要与预期一致）：标准输出只写一行 `match`，退出码为 0。

  ```text
  match
  ```

- 不匹配（文件读取和计算成功，但摘要不同）：标准输出只写一行 `mismatch`，
  退出码为 3。

  ```text
  mismatch
  ```

  以上两种结果都以换行结尾，标准错误为空。

- 核对对象与 `digest` 完全相同：文件从头到尾的原始字节，不做任何文本转换，
  换行、空白和二进制零字节都参与计算；文件名和其他文件属性不参与。文件移动
  或改名后，只要内容相同仍会匹配；空文件也可以核对。与 `digest` 一样按固定
  大小的块流式处理，内存占用不随文件大小增长。
- 预期摘要必须严格为 `sha256:` 后接 64 个**小写**十六进制字符：不接受省略
  前缀、大写字符、其他算法名称、额外空白或任何尾随内容。
- 错误时标准输出为空，标准错误给出信息：
  - 缺少参数、多传参数、空路径或摘要格式不符等用法错误：打印包含
    `verify-digest` 的用法说明，退出码为 2。路径与摘要同时有问题时，也优先
    按用法错误处理，不会把格式错误报成内容不匹配。
  - 路径不存在、对象不是普通文件、无法读取或摘要计算失败：说明原因并包含
    传入的路径，退出码为 1；这种情况下不会输出 `mismatch` 或任何成功结果。

> 这个功能只能核对文件内容与你**已有的一份摘要记录**是否一致。匹配结果不证明
> 发布者身份，也不构成有效的数字签名；若摘要记录本身在传输或保存过程中被篡改，
> 本命令无法发现。需要确认来源身份时，应使用数字签名等机制。

### 查询公钥指纹

从不同来源拿到一份公钥文件后，可以用稳定的指纹核对它们是否是同一把公钥。
公钥文件必须是普通文件，内容为一份以 `PUBLIC KEY` 标记包裹的 PEM 格式
SubjectPublicKeyInfo 公钥（即常见的 `-----BEGIN PUBLIC KEY-----` 块），至少支持
RSA 和 Ed25519。

```sh
./build/sealmark key-id ./keys/example.pub
```

- 指纹定义为公钥的 **SubjectPublicKeyInfo DER 表示的 SHA-256**，其中包含公钥
  算法标识和公钥值本身；文件名、路径以及 PEM 文本的排版方式都不参与计算。
  同一把公钥无论使用 LF 还是 CRLF 换行、Base64 如何分行（甚至一行排满或不写
  末尾换行），指纹都完全一致；文件移动或改名后结果也不变。
- 成功时标准输出只写一行 `spki-sha256:<指纹>`（指纹为 64 个小写十六进制字符，
  行末有换行），标准错误为空，退出码为 0。例如：

  ```text
  spki-sha256:339e2ff917630507b6a423b5ce084e285d1fa65d93b3e27a6195d3bbebc9ae23
  ```

  从两个渠道分别取得公钥文件后，各自运行一次 `key-id` 并比较两行输出即可：
  指纹相同才可能是同一把公钥，不同则一定不是。文件只被读取，不会被改写。

- 文件中**只能有一份**上述公钥：块的前后允许出现 ASCII 空白（空格、制表符、
  回车、换行等），其余内容一律拒绝，不会找到第一份公钥后忽略余下字节。空文件、
  Base64 编码损坏或被截断、含有多份公钥、夹带非空白内容，以及私钥
  （`PRIVATE KEY` 等）、证书（`CERTIFICATE`）或其他公钥封装（例如 PKCS#1 的
  `RSA PUBLIC KEY`）都属于无效输入。
- 失败时标准输出为空，不会退回到文件摘要，也不会输出部分指纹，标准错误说明
  原因：
  - 路径不存在、对象不是普通文件、读取失败或公钥内容无效：说明原因并包含
    传入的路径，退出码为 1。
  - 缺少路径、空路径或多传参数等用法错误：打印包含 `key-id` 的用法说明，
    退出码为 2。

> 指纹的作用只是**识别公钥**：它把一把公钥压缩成便于比较的固定长度值，可以
> 用来核对不同文件是否代表同一把公钥。指纹本身不证明这把公钥属于某个发布者
> ——任何人都能为任意公钥计算出同样的指纹；确认归属需要带外核验或基于签名的
> 信任机制。指纹也不代表任何文档已经通过该公钥对应的私钥签名验证，它与文档
> 签名的验证结果无关。
